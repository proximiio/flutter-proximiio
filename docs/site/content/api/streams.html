All streams are broadcast streams that stay open for the life of the app. They deliver events while the SDK runs (stateChanges and permissionUpdates also while stopped) and survive stop and start. A stream error is a ProximiioException.

StreamEventDelivers
stateChangesProximiioStateThe state after each lifecycle call
permissionUpdatesPermissionStatusPermission changes, also from the system settings
positionsPositionUpdateDevice positions
floorChangesFloorChangeEventFloor changes
geofenceEventsGeofenceEventGeofenceEntered, GeofenceExited, PrivacyZoneEntered, PrivacyZoneExited
privacyZoneStateChangesPrivacyZoneStateWhether the position is private
venueDataChangesVenueDataChangeWhich kinds of venue data changed
syncEventsSyncEventSyncUpdated, SyncDeleted, SyncCompleted, SyncFailed, StoreRecreated
beaconEventsBeaconEventBeaconFound, BeaconUpdated, BeaconLost, BeaconTelemetryReceived

Sealed events

GeofenceEvent, SyncEvent and BeaconEvent are sealed classes. A switch over them is exhaustive:

final text = switch (event) {
  GeofenceEntered(:final geofence) => 'in ${geofence.name}',
  GeofenceExited(:final geofence, :final dwellTime) => 'left ${geofence.name} after $dwellTime',
  PrivacyZoneEntered(:final zone) => 'private: ${zone.name}',
  PrivacyZoneExited(:final zone) => 'public again: ${zone.name}',
};

In widgets

StreamBuilder<PositionUpdate>(
  stream: sdk.positions,
  builder: (context, snapshot) => Text(snapshot.data?.coordinate.toString() ?? 'Locating…'),
)

Events emitted before a listener subscribes are not replayed. Seed the widget with lastPosition() if it needs a value at once.
