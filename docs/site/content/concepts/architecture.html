flutter_proximiio contains no positioning code. Each call goes to the native Proximi.io SDK v6 of the platform: the Swift SDK on iOS, the Kotlin SDK on Android. Both native SDKs implement the same API.

Layers

LayerWhat it does
Dart API (Proximiio, models)Typed Dart classes, Futures and Streams with the native names.
Bridge (generated)Typed platform channels generated with Pigeon from one schema.
Native bridgeSwift and Kotlin code that calls the SDK, converts the results and forwards the SDK streams.
Proximi.io SDK v6Positioning, venue data sync, geofencing, wayfinding.

One SDK instance per process

Proximiio.create creates the native SDK instance and stores it as the process-wide instance (Proximiio.shared in both native SDKs). Calling create again stops the previous instance and replaces it; Proximiio objects created earlier then address the new instance.

Several Flutter engines in one process (add-to-app, a background engine) share the instance. The engine that sets it up calls Proximiio.create; the others call Proximiio.shared(), which returns the running instance without stopping it, or null before create. Each engine receives every event on its own streams. Lifecycle calls (create, authenticate, start, stop, signOut) from all engines run one at a time.

When the last engine is destroyed on Android, the plugin stops the SDK unless the configuration runs the foreground service (android: options with a mode other than disabled). With the service the SDK keeps positioning, reporting geofences and uploading visitor analytics for as long as Android keeps the service; the next engine reaches it with Proximiio.shared() and can stop it.

The map plugin

flutter_proximiio_map reads the same process-wide instance. Create the SDK with Proximiio.create before showing a map; the map then shows the position, floor and routes of that instance.

Versions

Each plugin release pins one iOS SDK and one Android SDK version. The plugin version follows the SDK line (6.0.0-beta.N). See Versioning and releases.
