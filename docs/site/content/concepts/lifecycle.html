The SDK moves through five states. The lifecycle calls change the state; the streams report it.

StateMeaningReached by
idleCreated, not authenticatedProximiio.create, signOut
authenticatedToken accepted, not positioningauthenticate, stop
startingstart in progressstart
runningPositioningstart
stoppingstop in progressstop

Order of calls

  1. Proximiio.create(configuration)
  2. requestPermissions()
  3. authenticate(): validates the token with the API and applies stored venue data.
  4. start(): starts positioning, sync, geofencing and the event streams.
  5. stop(): stops them. start() can be called again.
  6. signOut(): stops, forgets the token and clears the stored data.

start throws notAuthenticated until authenticate has succeeded once on this instance.

State

final state = await sdk.state();
sdk.stateChanges.listen((state) => print('SDK is ${state.name}'));

The native SDKs have no state stream. stateChanges reports the state after each lifecycle call made through the plugin.

The Dart streams do not end: listen once, at any time, and keep the subscription across stop and start. Events emitted before the listener subscribes are not replayed; read the current values with lastPosition, currentFloor or enteredGeofenceIds.

Every stream is a broadcast stream: several listeners share one native subscription. A stream error is a ProximiioException.

Flutter app lifecycle

The SDK does not follow the app's lifecycle by itself. To position only in the foreground, call stop when the app is paused and start when it resumes. See Foreground positioning and Background positioning.
