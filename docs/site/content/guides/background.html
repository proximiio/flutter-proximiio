Background positioning keeps the SDK running when the app is not visible. Each platform needs its own setup; the Dart code is the same.

Prerequisites

  • The always location permission: requestPermissions(always: true).
  • A reason the user accepts. Both stores review background location use.

Configure

final sdk = await Proximiio.create(
  const ProximiioConfiguration(
    token: token,
    allowsBackgroundLocationUpdates: true,
    android: AndroidServiceOptions(
      notificationTitle: 'Indoor navigation',
      notificationText: 'Showing your position in the venue',
      notificationIcon: 'ic_stat_positioning',
    ),
  ),
);
await sdk.requestPermissions(always: true);

iOS

  1. Add location to UIBackgroundModes in Info.plist.
  2. Add NSLocationAlwaysAndWhenInUseUsageDescription.
  3. Set allowsBackgroundLocationUpdates: true.
<key>UIBackgroundModes</key>
<array>
  <string>location</string>
</array>

Android

On Android a foreground service keeps the process alive. The SDK declares the service and its permissions. It runs only when the configuration has android: options; without them the SDK runs no service and positioning stops once Android freezes the backgrounded process. An empty AndroidServiceOptions() runs the service with the defaults below.

SettingDefaultPurpose
modeenableddisabled: no service; required: positioning does not start without it
notificationTitleIndoor positioningNotification title
notificationTextLocating you inside this venueNotification text
notificationIconThe app iconName of a drawable in the app
channelNameIndoor positioningNotification channel shown in the system settings
holdsWakeLockfalseHold a partial wake lock while positioning

Change the notification while running:

await sdk.android.updateServiceNotification(
  const AndroidServiceOptions(notificationText: 'Navigating to Gate B12'),
);
await sdk.android.resetServiceNotification();

updateServiceNotification returns false when the service is not running. Both calls throw ProximiioErrorCode.unsupported on iOS.

When Android refuses to start the foreground service from the background, the SDK positions only while the app is in the foreground.

Verify

Start positioning, lock the device and walk. positions keeps delivering updates with background: true.
