The plugin is a Dart package with native code for iOS and Android. Each platform needs a few build settings that the native Proximi.io SDK v6 requires.

Requirements

PlatformMinimum
Flutter / DartFlutter 3.44, Dart 3.12
iOSiOS 15.0, Xcode 16
AndroidminSdk 26, compileSdk 37, Android Gradle Plugin 8.13, JDK 17

Add the package

dependencies:
  flutter_proximiio:
    git:
      url: https://github.com/proximiio/flutter-proximiio
      ref: 6.0.0-beta.4

Pin ref to a release tag. A git dependency without ref follows the default branch.

iOS

CocoaPods

The Proximi.io SDK pod is not on the CocoaPods trunk. Add it to ios/Podfile inside the Runner target, at the iOS SDK version that matches the plugin release, and set the platform to iOS 15: 

platform :ios, '15.0'

target 'Runner' do
  use_frameworks!
  pod 'Proximiio', :podspec => 'https://raw.githubusercontent.com/proximiio/proximiio-sdk-ios-binary/6.0.0-beta.66/Proximiio.podspec'

  flutter_install_all_ios_pods File.dirname(File.realpath(__FILE__))
end

Then run pod install in ios/, or let flutter run do it.

Swift Package Manager

With Flutter's Swift Package Manager support turned on (flutter config --enable-swift-package-manager), the plugin's own package pulls the SDK from proximiio/proximiio-sdk-ios-binary. The Podfile line above is not needed.

Info.plist

Add all six usage descriptions, also when the app does not use the feature. App Store validation checks them against the APIs the SDK links and rejects an upload without them (ITMS-90683).

KeyShown when
NSLocationWhenInUseUsageDescriptionPositioning is asked
NSLocationAlwaysAndWhenInUseUsageDescriptionBackground positioning is asked (always: true)
NSBluetoothAlwaysUsageDescriptionBeacon positioning is asked
NSMotionUsageDescriptionPDR is asked; floor changes from the barometer
NSNearbyInteractionUsageDescriptionUWB anchors are ranged
NSCameraUsageDescriptionCamera-assisted UWB direction

A missing key turns its input off: the SDK logs an error naming the key and reports that permission as denied. Without NSBluetoothAlwaysUsageDescription no beacons are scanned; without a location key the location permission resolves as denied.

For background positioning also add location to UIBackgroundModes. See Background positioning.

Scene lifecycle

An app built with Xcode 27 that has not adopted the UIScene lifecycle ends at launch on iOS 27. Flutter 3.41 and newer migrate an unmodified AppDelegate and Info.plist on the next build. For a custom AppDelegate, follow Flutter's UIScene adoption guide. The plugin works with either lifecycle.

Android

Repository

The SDK is published to https://maven.eu.proximi.fi/releases/ (public, no credentials). The plugin adds the repository to every Gradle project. When settings.gradle.kts uses RepositoriesMode.FAIL_ON_PROJECT_REPOS, add it there: 

dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven("https://maven.eu.proximi.fi/releases/")
    }
}

Build settings

A project created with Flutter 3.44 or newer uses the Android Gradle Plugin 9 and Gradle 9, which run on the JDK that Android Studio bundles. Raise compileSdk and minSdk in android/app/build.gradle.kts: 

android {
    compileSdk = 37
    defaultConfig {
        minSdk = 26
    }
}

The plugin builds with and without the Android Gradle Plugin's built-in Kotlin (android.builtInKotlin in android/gradle.properties).

An older project needs the Android Gradle Plugin 8.13 or newer and Gradle 8.13 or newer. Gradle versions before 9.1 do not run on JDK 25; see Troubleshooting.

The Android Gradle Plugin 8.9 that older Flutter templates use cannot compile against API 37. The build then fails with Failed to find Platform SDK with path: platforms;android-37.

Manifest

The SDK's manifest adds the location, Bluetooth, foreground-service and notification permissions and its foreground service to the app. Nothing has to be declared by hand. To keep an app foreground-only, remove background location: 

<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
    <uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" tools:node="remove" />
</manifest>

Verify

flutter build ios --no-codesign and flutter build apk succeed. In the app, await Proximiio.create(...) returns without an error.
