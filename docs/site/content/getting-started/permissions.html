requestPermissions asks for location, Bluetooth and, on Android, notifications, and returns a PermissionStatus. Call it from the foreground, before start. 

final status = await sdk.requestPermissions(always: false);
if (!status.isLocationAuthorized) {
  // Positioning cannot start.
}

What is asked

PermissioniOSAndroid
LocationWhen in use; with always: true also alwaysFine and coarse location; with always: true background location in a second prompt
BluetoothAsked by the plugin unless the preset is relayOnly; needs NSBluetoothAlwaysUsageDescriptionBLUETOOTH_SCAN and BLUETOOTH_CONNECT on Android 12 and newer, asked by the plugin unless the preset is relayOnly
NotificationsNot askedPOST_NOTIFICATIONS on Android 13 and newer, when the configuration runs the foreground service (android: options with a mode other than disabled)
MotionNot asked by requestPermissions; start shows the prompt for the barometer unless barometerEnabled: false; for PDR call requestMotionPermissionNot asked; call requestMotionPermission

Each permission is asked once. A permission the user has answered is not asked again; to change it, the user goes to the system settings.

Motion is needed only for PDR (enablePdr) and, on iOS, for barometric floor changes. The compass (compassHeadings) needs no permission. On Android, background location is a separate prompt because Android 11 and newer deny it when it is asked together with foreground location.

iOS shows the upgrade to background location ("Change to Always Allow") once per installation. When it was used before, requestPermissions(always: true) returns the current status without a prompt.

Reading the status

FieldValues
locationnotDetermined, whenInUse, always, denied, restricted
accuracyfull, reduced
bluetoothnotDetermined, allowed, denied, restricted
motionnotDetermined, authorized, denied, restricted, unavailable

start does not check permissions. Without location, or with accuracy: reduced (approximate location), it succeeds but indoor positioning produces no positions. Check the status before start; diagnostics().noPositionReason reports the cause afterwards.

Changes made in the system settings

permissionUpdates emits a new status whenever the user changes a permission, also in the system settings. On Android the change is read when the app comes back to the foreground. 

sdk.permissionUpdates.listen((status) {
  if (!status.isLocationAuthorized) {
    // Show why positioning stopped.
  }
});

Android activity

The prompts need an attached activity. Any FlutterActivity works. Without one (for example in a background engine), requestPermissions returns the current status without asking.
