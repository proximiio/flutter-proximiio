A basic integration creates the SDK, asks for permissions, authenticates, starts positioning, listens to positions and stops the SDK with the app.

Prerequisites

  • An application token from the Proximi.io Portal. Keep it out of version control: pass it with --dart-define-from-file from a git-ignored file, as the example app does.
  • A physical device for beacon positioning. Simulators and emulators have no Bluetooth; use a simulated route there.
  • The platform setup from Installation.

The lifecycle

The order is fixed: create → requestPermissions → authenticate → start → listen → stop. Every method returns a Future and throws ProximiioException on failure. 

import 'dart:async';

import 'package:flutter_proximiio/flutter_proximiio.dart';

const token = String.fromEnvironment('PROXIMIIO_TOKEN');

Future<Proximiio> startPositioning() async {
  final sdk = await Proximiio.create(const ProximiioConfiguration(token: token));

  final permissions = await sdk.requestPermissions();
  if (!permissions.isLocationAuthorized) {
    throw StateError('Location permission is needed for indoor positioning.');
  }

  await sdk.authenticate();
  await sdk.start();
  return sdk;
}

Listen to positions

final StreamSubscription<PositionUpdate> subscription = sdk.positions.listen((position) {
  final floor = position.floor;
  print('${position.coordinate.latitude}, ${position.coordinate.longitude} '
      '±${position.horizontalAccuracy} m, floor ${floor?.name ?? floor?.level}, ${position.source.name}');
});

Streams can be listened to before start and stay open across stop and start. Cancel the subscription when the screen goes away.

Stop

await subscription.cancel();
await sdk.stop();

stop ends positioning and reports an exit for every geofence the device is in.

Handle errors

try {
  await sdk.authenticate();
  await sdk.start();
} on ProximiioException catch (error) {
  switch (error.code) {
    case ProximiioErrorCode.invalidToken:
      // The token is wrong or revoked; retrying does not help.
      rethrow;
    case ProximiioErrorCode.api when error.isRetryable:
      // No connection or a server error: retry later.
      break;
    default:
      rethrow;
  }
}

authenticate validates the token with the Proximi.io API and needs a connection. start throws notAuthenticated until authenticate has succeeded. Without the location permission start succeeds but produces no positions; check the permission status first.

Verify

On a device inside a configured venue, stateChanges reports running and positions delivers updates with a floor. Outside a venue, positions come from the platform location service (PositionSource.native).
